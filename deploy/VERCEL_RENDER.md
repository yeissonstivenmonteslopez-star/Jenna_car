# Despliegue de Jenna Car

Usa las plantillas de esta carpeta, `.env.render.example` y `.env.vercel.example`. Sustituye los dominios de ejemplo por los asignados a tus proyectos. Para preparar copias locales usa los nombres `.env.render` y `.env.vercel`, que Git ignora. En Render introduce los valores en las variables del Blueprint o en Environment del servicio. En Vercel introdúcelos en Environment Variables del proyecto para Production antes de compilar. Los archivos de Docker y desarrollo corresponden a otros entornos.

1. Importa el repositorio como Blueprint en Render con el archivo `render.yaml`. El plan Starter y el disco de 1 GB tienen costo. El disco conserva las fotos nuevas entre despliegues. Si existen fotos locales que deban seguir disponibles, copia sus carpetas `profile-photos` y `reparaciones` a ese disco.
2. Configura `DATABASE_URL` con la URI de la base de la aplicación en formato `mysql+pymysql://`. Conserva los caracteres de contraseña codificados para URL. Descarga la CA del proyecto Aiven y añádela como Secret File de Render con nombre `ca.pem`. Si Aiven restringe las IP, autoriza las IP de salida del servicio Render. Comprueba que `/api/health/ready` responda 200 tras desplegar.
3. Importa el mismo repositorio en Vercel con raíz `frontend`, preset Vite, compilación `npm run build` y salida `dist`. Configura `VITE_API_URL` con el origen HTTPS de Render, sin `/api`. Para el inicio con Google configura también `VITE_GOOGLE_CLIENT_ID`, el mismo ID en `GOOGLE_CLIENT_IDS` en Render y el origen de Vercel entre los orígenes autorizados en Google.
4. En Render asigna a `FRONTEND_ORIGIN` el origen HTTPS de Vercel sin barra final. Usa ese origen seguido de `/mis-recibos` para `MERCADOPAGO_RETURN_URL`. Para recuperación de contraseña configura `MAIL_USERNAME`, `MAIL_PASSWORD` y `MAIL_FROM` en el servicio de Render. Con Gmail, `MAIL_PASSWORD` debe ser una contraseña de aplicación (requiere verificación en dos pasos), no la contraseña normal. El Blueprint usa `smtp.gmail.com` con SSL en el puerto 465; para otro proveedor SMTP también configura `MAIL_HOST`, `MAIL_PORT`, `MAIL_USE_TLS` y `MAIL_USE_SSL`. Render bloquea SMTP en servicios Free; los servicios pagos admiten 465 y 587.
5. En la aplicación de producción de Mercado Pago configura el evento de pagos con la URL HTTPS de Render seguida de `/api/pagos/mercado-pago/webhook`. Guarda esa URL en `MERCADOPAGO_WEBHOOK_URL` y el secreto de firma de esa aplicación en `MERCADOPAGO_WEBHOOK_SECRET`. Guarda el token de producción en `MERCADOPAGO_ACCESS_TOKEN`. Estos secretos pertenecen al backend. Aplica los cambios y vuelve a desplegar Vercel si cambiaste una variable Vite.
6. Para validar el primer cobro autorizado, abre un recibo enviado y pendiente, verifica su total en el checkout y compara el ID de operación y el total pagado en Mercado Pago con el recibo confirmado por el webhook. Una discrepancia requiere conciliación en Mercado Pago, incluida la devolución si corresponde.
